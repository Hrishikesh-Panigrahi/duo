# Gotchas

Things that have cost time before. Add to this when something surprises you.

## Build and CSS

- **Tailwind 4 scans text files that aren't gitignored.** It skips binaries, CSS, lockfiles, `.gitignore`, `.env*`,
  `.git/` and `node_modules/`. A word like
  `static` or `hidden` in a doc becomes a CSS rule.
  - `src/index.css` excludes `docs/`, `scripts/`, `.claude/` and `CLAUDE.md` with `@source not`. A new non-UI
    folder needs its own line.
  - `README.md`, `supabase/` and the root config files are still scanned. Today they add no rules.
  - To check the CSS is unchanged, build from a clean `git archive` export, not from a working tree.
- **The service worker can serve the previous bundle.** `main.tsx` registers it with `registerSW({ immediate: true })`
  in autoUpdate mode. After a rebuild, the page keeps running the old bundle until the new worker activates and
  reloads it, so one view (or a test mid-run) can come from the old code. Before trusting a result, unregister the
  worker and clear Cache Storage, or use a fresh profile.
- `npm run build` runs `tsc --noEmit` first. TypeScript 7 is the native compiler, so its error text can differ from
  older tsc.
- `dist/_headers` is generated by `vite.config.ts` during `vite build`. `npm run dev` sends none of these headers.

## Database

- **Ciphertext checks are `NOT VALID`.** They block plaintext on every new insert or update, but rows from before
  encryption can still be plaintext. Code must not assume every row has a `cipher`.
- **A `spaces` or `members` row from before encryption** fails any update until its plaintext name is cleared.
  - For spaces, `enable_e2e` and `join_space` (`direct_media` migration) and `renameSpace` clear it.
  - For members, `renameMe` clears `display_name`.
- **Messages can't be updated** (there's no UPDATE grant). A legacy message is swapped for an encrypted copy by
  `encrypt_legacy_message`, and only its sender can do that.
- `supabase/config.toml` enables seeding on `db reset` from `./seed.sql`, but there's no `supabase/seed.sql` in
  the repo. A reset gives empty tables.
- `App.tsx`'s "not configured" screen says to run only `…_init.sql`, but the app needs all four migrations.

## Realtime

- supabase-js uses Realtime protocol 2.0.0 (realtime-js's default). **Broadcasts (typing, signals) travel as binary
  frames**, while presence and `postgres_changes` are JSON text. A text search over a capture misses broadcasts
  unless you decode the frames. A typing ping sent before the room has joined goes as a JSON REST request instead.
- `supabase.channel(name)` returns any existing channel with that name, even one still being torn down.
  `SpaceSync` adds a random suffix to its channel name, and `Room` frees its name before reopening.
- Subscriptions are unfiltered, because `postgres_changes` can't filter DELETEs. RLS limits inserts and updates to
  the space. DELETE events carry only the id and can arrive for any space. `SpaceSync.applyChange` drops inserts and
  updates from other spaces and passes every DELETE on; removing an id that isn't loaded does nothing.
- `PresenceGate` allows 4 presence changes per 30 s. The comment in `room.ts` gives the server's limit as 5.

## UI testing

- A `Field` with a `hint` includes the hint in its label, so an exact label match fails. Match by role or position.
- The bottom bar uses buttons, not tabs. The Chat button's name includes its unread badge (for example "Chat 1").
- A text bubble's text sits next to its timestamp, not in a leaf element of its own. Emoji-only messages, links and
  contact cards are separate elements.
- An email field's built-in validation blocks submitting markup. Use a valid email when testing hostile input in
  other fields.
- Random base64 can contain short real words, so a "this word never appears" check on ciphertext needs long or
  unusual markers.
- To corrupt a ciphertext character, change it to a *different* one: replacing `A` with `A` is no change.
- Long-press targets may be off screen. Scroll them into view first.

## Services (set up outside this repo)

- **Applying migrations to the live project:** run each file in the SQL editor (or `supabase db push`). Wrap the
  file in `begin; … commit;`. Check the editor really holds the file before pressing Run, because `/sql/new` can
  reopen an older snippet over it.
- Supabase Free projects pause after a week idle; resume them from the dashboard.
- Local Supabase needs Docker. To pipe SQL from a heredoc into the database container, use `docker exec -i`
  (with `-i`).
